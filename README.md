# 连锁药房批号效期台账

总仓 + 8 家门店共用的药品批号/效期管理系统。浏览器打开即用，数据全在总仓这台电脑的
`data/pharmacy.db`（SQLite）里。

## 快速开始（总仓老电脑）

1. 装一次 Python 3.10+（安装时勾选 **Add python.exe to PATH**）；
2. 双击 **`启动台账系统.bat`** —— 它会自动：建虚拟环境 → 装依赖 → 建库 →
   首次灌入演示数据（15 药品 / 30 批次 / 8 门店 / 近三个月流水）→ 起服务 → 弹开浏览器；
3. 门店电脑与总仓在同一局域网，浏览器直接打开启动窗口里显示的
   `http://<总仓IP>:8000` 即可，无需装任何东西。

停止系统：关掉启动窗口。数据一直在 `data/pharmacy.db`，删库重来的话删掉该文件再启动即可。

## 五条铁规矩是怎么落地的

| 规矩 | 实现 |
|---|---|
| 入库五要素缺一不可 | 批号/生产日期/有效期至/数量/供应商在 API 层强制（缺则 422），同药同批号再入库时生产日期、有效期必须与台账一致 |
| 出库先出效期最近的批 | `services/outbound.py`：FEFO 自动分配，一批不够才动下一批；手工指定批次也必须与 FEFO 结果一致，否则拒单并点名应先出的批号 |
| 每动一批留流水 | `stock_ledger` 表记录全部数量变动（含调拨在途、拆零），带变动后结存 |
| 效期前 6 个月标近效期；过期当天整批锁死 | `services/expiry_lock.py`：近效期自动判定；过期批在任何动账前被置为终态 `EXPIRED_LOCKED`，系统内没有解锁入口 |
| 质检停售/放行 | 停售即禁止出库调拨；放行必须填质检放行单号（空单号 400）；已过期批永远不能放行 |
| 召回一口气查清 | `services/recall.py`：输批号 → 各门店在手/已售/调入调出 + 在途调拨明细，并自动对账（总入库 = 在库 + 已售 + 在途） |
| 两人同时出最后一批不卖穿 | SQLite `BEGIN IMMEDIATE` 事务 + 条件更新 `UPDATE … WHERE quantity >= n`，影响行数不为 1 即整单回滚；数据库层还有 `CHECK(quantity >= 0)` 兜底，账上不可能出现负数 |
| 拆零不混整盒 | 拆零销售走独立出库类型，单独写 `split_records` 拆零台账 |
| 每月 1 号看上月 | 月度报表页默认上月：近效期清单 + 批次流向表（期初/入库/销售/拆零/调入/调出/期末），全部由流水汇总，可逐笔对账 |

## 验收指南（对应您要亲自验的五件事）

1. **并发不超卖**：开两个浏览器窗口进「出库销售」，选同一门店同一药品同时点"确认出库"。
   合计扣减不会超过库存，超出的那笔会看到"可售库存不足"；「库存查询」里不会出现负数。
   （自动化版本：`cd backend && python -m pytest tests/ -q`，12 线程抢 100 盒。）
2. **过期批/停售批拦截**：种子里的 `CTR2409B`（注射用头孢曲松钠，2026-08-31 到期，已锁死）
   和 `GLU2607B`（葡萄糖注射液，质检停售）——出库页选它们会被拒并说明原因；
   去「质检管理」给过期批放行，同样被拒（"任何人不可放行"）。
3. **FEFO 纠错**：出库页勾"手动指定批次"，故意给效期远的批填数量、跳过效期近的批，
   提交即被拒，错误信息会点名应当先出的批号和效期。
4. **召回追溯**：「召回追溯」输 `AMX2601A` —— 总入库 2000 盒，5 个点的在手/已售、
   总仓剩 900、还有 100 盒压在总仓→人民路店的在途调拨单上，对账"账实相符"。
5. **月报对账**：「月度报表」选 `2026-08`：近效期清单含 `HQZ2510B`、`VTC2511B` 和已过期
   的 `CTR2409B`；批次流向表每行 期初+入库+调入−销售−拆零−调出=期末，
   可与「库存流水」逐笔核对。

## 技术栈与结构

后端 Python + FastAPI + SQLAlchemy + SQLite（WAL + busy_timeout + BEGIN IMMEDIATE）；
前端 Vue 3 + Vite（构建产物在 `backend/app/static`，由 FastAPI 托管，老电脑无需 Node）。

```
backend/app/
├── services/
│   ├── outbound.py     # 模块一：出库扣减（FEFO 分配、条件更新、事务）
│   ├── expiry_lock.py  # 模块二：效期锁定（过期锁死、近效期判定）
│   ├── recall.py       # 模块三：召回追溯（全链流向 + 对账）
│   ├── reports.py      # 模块四：报表（月报、近效期清单）
│   ├── inbound.py      # 入库服务
│   ├── transfers.py    # 调拨服务（在途/收货）
│   └── qc.py           # 质检停售/放行
├── routers/            # API 路由
├── models.py           # 数据模型（数量全整数，库存 CHECK >= 0）
├── seed.py             # 种子：15 药品/30 批次/8 门店/近三月流水
└── main.py
backend/tests/test_acceptance.py  # 16 项验收测试
启动台账系统.bat                  # 双击启动器
```

四个核心模块各管各的：扣减只走 `outbound.deduct_inventory` 一个出口；
效期规则只在 `expiry_lock`；流向计算只在 `recall`；报表只读流水不改账。

## 开发模式（可选）

```bash
cd backend && pip install -r requirements.txt -r requirements-dev.txt
python -m pytest tests/ -q          # 跑验收测试
uvicorn app.main:app --reload       # 后端热重载
cd frontend && npm install && npm run dev    # 前端热重载（代理到 8000）
npm run build                       # 重新构建到 backend/app/static
```
